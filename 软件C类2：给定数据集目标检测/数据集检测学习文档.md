# 数据集检测学习文档

## 一、项目目标

使用 **YOLO11n** 训练目标检测模型，识别以下三类目标：

| 类别 ID | 类别名称 | 说明 |
|---------|----------|------|
| 0 | `community_person` | 本小区人员 |
| 1 | `non_community_person` | 非本小区人员 |
| 2 | `electric_bike` | 电动车 |

> YOLO（You Only Look Once）是一种单阶段目标检测算法，特点是速度快、精度高，非常适合实时场景。YOLO11n 是 Ultralytics 推出的最新系列中最小的版本（nano），参数量少、推理快，适合在算力有限的设备上部署验证。

## 三、数据集结构

数据集按照 YOLO 标准格式组织，目录结构如下：

```
dataset/
├── images/
│   ├── train/          # 训练集图片
│   └── val/            # 验证集图片
├── labels/
│   ├── train/          # 训练集标签（.txt，每个图片对应一个）
│   └── val/            # 验证集标签
└── data.yaml           # 数据集配置文件
```

`data.yaml` 内容示例：

```yaml
path: dataset
train: images/train
val: images/val

nc: 3
names:
  - community_person
  - non_community_person
  - electric_bike
```

> YOLO 的标签文件是纯文本格式，每行代表一个目标：`class_id cx cy w h`，坐标都是归一化到 [0, 1] 的相对值。这种格式紧凑、易读，也方便脚本批量处理。

## 四、训练代码

```python
from ultralytics import YOLO

# 加载预训练权重（COCO 上预训练的 YOLO11n）
model = YOLO("yolo11n.pt")

# 开始训练
model.train(
    data="dataset/data.yaml",   # 数据集配置文件路径
    epochs=50,                  # 训练轮数
    imgsz=640,                  # 输入图片缩放尺寸
    batch=4,                    # 批次大小（CPU 下不宜过大）
    name="community_v1-5"       # 本次实验命名，结果保存在 runs/detect/ 下
)
```

> 关键参数解读：
> - **`imgsz=640`**：YOLO 会将所有图片统一缩放到 640×640 再送入网络，这是速度与精度的一个平衡点。
> - **`batch=4`**：CPU 内存有限，batch 太大会 OOM（内存溢出），4 是一个保守但稳妥的值。
> - **`name`**：每次实验起不同的名字，方便对比不同版本的效果，避免结果互相覆盖。

## 五、验证结果

### 整体指标

| 指标 | 数值 | 含义 |
|------|------|------|
| P（Precision） | 0.93 | 精确率：模型预测为正的样本中，真正为正的比例 |
| R（Recall） | 0.931 | 召回率：所有正样本中，模型成功找出的比例 |
| mAP50 | 0.931 | IoU 阈值为 0.5 时的平均精度均值 |
| mAP50-95 | 0.619 | IoU 从 0.5 到 0.95 逐步提升的平均精度均值 |

### 分类别指标

| 类别 | mAP50 | 分析 |
|------|-------|------|
| `community_person` | 0.987 | 表现优秀，接近饱和 |
| `non_community_person` | 0.812 | 偏低，是主要瓶颈 |
| `electric_bike` | 0.995 | 表现极佳 |

> **结果分析**：
> - `electric_bike` 和 `community_person` 的 mAP50 都在 0.98+，说明模型对这两类目标的检测已经非常可靠。
> - `non_community_person` 只有 0.812，明显低于其他两类，原因很可能是**样本数量不足或标注质量不均**。从改进方向来看，作者也意识到了这一点，计划增加该类样本。
> - mAP50-95 只有 0.619，说明当 IoU 阈值提高（要求更精准的框）时，模型表现下降明显，反映了**定位精度还有提升空间**。

## 六、模型权重

训练完成后，最佳权重保存在：

```
runs/detect/community_v1-5/weights/best.pt
```

> Ultralytics 会在训练过程中自动保存两个权重文件：`best.pt`（验证集上表现最好的）和 `last.pt`（最后一个 epoch 的）。实际部署时优先使用 `best.pt`。

---

## 七、推理方式

```python
from ultralytics import YOLO

model = YOLO("runs/detect/community_v1-5/weights/best.pt")

# 对单张图片推理
model.predict(source="test.jpg", save=True, conf=0.25)

# 对整个文件夹推理
model.predict(source="test_images/", save=True, conf=0.25)
```

| 参数 | 说明 |
|------|------|
| `source` | 图片路径、文件夹路径、视频路径，甚至摄像头 ID（如 `0`） |
| `save` | 是否将检测结果（带框的图片）保存到 `runs/predict/` |
| `conf` | 置信度阈值，低于该值的检测结果会被过滤掉 |

> `conf=0.25` 是一个相对宽松的阈值，适合召回优先的场景。如果实际应用中误检太多，可以适当调高到 0.5 或 0.7 来减少误报。

## 八、改进方向

| 序号 | 改进措施 | 预期效果 |
|------|----------|----------|
| 1 | 增加 `non_community_person` 样本 | 提升该类的 mAP，拉高整体指标 |
| 2 | 增加验证集数量 | 让验证结果更可靠，减少过拟合风险 |
| 3 | 优化标注框精度 | 提升定位精度，改善 mAP50-95 |
| 4 | 使用 GPU / CUDA 加速训练 | 大幅缩短训练时间，支持更大 batch |
| 5 | 尝试更多 epoch 或更大模型（如 YOLO11s/m） | 进一步提升精度上限 |

> 改进的核心思路可以总结为三点：**数据端**（加样本、修标注）、**算力端**（上 GPU）、**模型端**（换大模型 / 调超参）。建议优先解决数据问题，因为"garbage in, garbage out"——数据质量永远是第一位的。
