# *井字棋*学习文档
 一、项目概述
本项目实现一个基于 Q-Learning 的井字棋（Tic-Tac-Toe）智能体
通过自对弈（Self-Play）训练，并展示训练曲线和最终对弈 Demo
***
二、代码复现过程+设计逻辑
整个项目被封装在一个 Python 文件中，包含四个核心类/模块：
1. TicTacToeEnv：环境模拟器
    1.状态空间（State Space）：使用长度为 9 的一维列表表示棋盘。0代表空位，1代表 X，2代表 O。为了能作为字典的 Key，状态被转换为 tuple
    2.动作空间（Action Space）：0 到 8 的整数，对应棋盘的 9 个位置
    3.合法落子判断：get_legal_actions()方法遍历棋盘，返回所有值为 0的索引。这是防止智能体选择已被占用的格子（Invalid Action）的关键
    4.胜负判断：_check_win()内部预定义了 8 种获胜组合（3行、3列、2对角线），检查当前玩家是否占据其中任意一组
2. QAgent：Q-Learning 算法载体
    1.Q-Table 存储：使用 Python 字典 {(state, action): q_value}存储 Q 值。相比二维数组，字典在处理稀疏状态空间时更高效（很多棋局状态不会出现）。
    2.以概率 随机选择动作（探索）
    3.以概率 选择当前 Q 值最大的动作（利用）
3. Reward Design：奖励函数（独立函数）
    1.获胜​	+1.0	强正反馈，鼓励智能体追求胜利
    2.失败​	-1.0	强负反馈，惩罚导致失败的走法
    3.平局​	0.0	中性反馈
每一步​	-0.01	Time Penalty（时间惩罚），鼓励智能体尽快获胜，避免无意义地拖延回合
4. Training Loop：训练控制流
    1.初始化两个智能体（Agent1 执 X，Agent2 执 O）
    2.循环进行 Episodes（对局）
    3.每局开始时重置棋盘
    4.双方轮流落子，直到游戏结束（Done）
    5.关键：两个智能体共享相同的学习逻辑，但在各自的视角下更新 Q 表。这种“左右互搏”的方式极大地丰富了训练数据
***
四、调参比对与分析
在开发过程中，主要调整了三个超参数：学习率、折扣因子和探索率
1.学习率
过大（如 0.9）：Q 值震荡剧烈，难以收敛，容易遗忘之前学到的正确走法
过小（如 0.001）：收敛速度极慢，训练 2 万局后仍表现不佳
最佳选择（0.1）：在保证收敛稳定性的前提下，拥有较快的学习速度
2. 折扣因子 
设置（0.9）：由于井字棋步数较少，未来的奖励依然很重要。意味着智能体会为了两步之后的胜利而努力布局
3. 探索率与衰减策略
固定 （0.1）：前期探索不足，训练初期容易陷入局部最优（例如只喜欢下角落，不懂防守）
衰减 ：代码中使用了 epsilon *= 0.9999
初期：高 保证充分探索各种走法
后期：低 保证利用已学到的知识，稳定胜率
调参结论：使用 ε-decay​ 策略的训练曲线比固定 ε 更加平滑，最终的胜率也更高

五、Debug 过程记录
在复现过程中，遇到了几个典型 Bug，记录如下：
1. Bug 1：ValueError: 非法落子
现象：程序运行时随机报错
原因：最初在更新 Q 值时，传入的 next_state对应的棋盘已经满了，但智能体仍试图从中选点
解决：确保在 env.step()之后检查 env.done，若结束则不再执行后续逻辑；在更新 Q 值时，如果 done为真，则 next_max_q设为 0
2. Bug 2：智能体从不 Block（不会防守）
现象：对手差一步就赢了，智能体却去下别的地方
原因：奖励函数中缺少对失败”的惩罚，或者奖励权重不合理
解决：将失败奖励明确设为 -1，并确保 Q 更新公式中 next_max_q计算正确，让智能体意识到某些走法会导致后续被击败
3. Bug 3：训练曲线剧烈震荡
现象：胜率在 0.4 到 0.8 之间来回跳动，无法收敛
原因：学习率 设置过高（0.5），导致新经验瞬间覆盖了旧记忆
解决：降低 至 0.1，并引入 ε 衰减机制，使训练后期趋于稳定
