# 井字棋学习文档

## 一、项目概述

本项目实现一个基于 **Q-Learning** 的井字棋（Tic-Tac-Toe）智能体，通过**自对弈（Self-Play）**训练，并展示训练曲线和最终对弈 Demo。

> 井字棋看似简单（3×3 棋盘、最多 9 步结束），但状态空间约有 3⁹ ≈ 19683 种，足以作为强化学习的入门验证平台。它的规则透明、胜负判定明确，非常适合验证 Q-Learning 的核心机制是否正常工作。

---

## 二、代码复现过程 + 设计逻辑

整个项目被封装在一个 Python 文件中，包含四个核心类/模块：

### 1. `TicTacToeEnv`：环境模拟器

| 设计要素 | 实现方式 |
|---------|---------|
| **状态空间（State Space）** | 使用长度为 9 的一维列表表示棋盘：`0` = 空位，`1` = X，`2` = O；转换为 `tuple` 以作为字典的 Key |
| **动作空间（Action Space）** | `0` 到 `8` 的整数，对应棋盘的 9 个位置 |
| **合法落子判断** | `get_legal_actions()` 遍历棋盘，返回所有值为 `0` 的索引，防止智能体选择已被占用的格子（Invalid Action） |
| **胜负判断** | `_check_win()` 内部预定义了 **8 种获胜组合**（3 行 + 3 列 + 2 对角线），检查当前玩家是否占据其中任意一组 |

### 2. `QAgent`：Q-Learning 算法载体

- **Q-Table 存储**：使用 Python 字典 `{(state, action): q_value}` 存储 Q 值。相比二维数组，字典在处理**稀疏状态空间**时更高效（很多棋局状态不会出现）。
- **ε-贪婪策略**：
  - 以概率 **ε** 随机选择动作 → **探索（Exploration）**
  - 以概率 **1−ε** 选择当前 Q 值最大的动作 → **利用（Exploitation）**

### 3. Reward Design：奖励函数（独立函数）

| 事件 | 奖励值 | 设计意图 |
|------|--------|---------|
| 获胜 | **+1.0** | 强正反馈，鼓励智能体追求胜利 |
| 失败 | **-1.0** | 强负反馈，惩罚导致失败的走法 |
| 平局 | **0.0** | 中性反馈 |
| 每一步 | **-0.01** | Time Penalty（时间惩罚），鼓励智能体尽快获胜，避免无意义地拖延回合 |

> 时间惩罚 -0.01 是一个"隐性教练"：它不改变胜负的最终信号，但会让智能体在多条获胜路径中**偏好更短的那条**。如果没有这个惩罚，智能体可能学会"磨蹭"——反正最后能赢，多走几步也无所谓。

### 4. `Training Loop`：训练控制流

1. 初始化两个智能体（`Agent1` 执 X，`Agent2` 执 O）
2. 循环进行 **Episodes**（对局）
3. 每局开始时**重置棋盘**
4. 双方**轮流落子**，直到游戏结束（`Done`）
5. **关键**：两个智能体共享相同的学习逻辑，但在各自的视角下更新 Q 表。这种**"左右互搏"**的方式极大地丰富了训练数据

> Self-Play 的核心价值在于：对手的水平会随着训练同步提升。Agent1 今天学会了一招进攻，明天 Agent2 就会被迫学会防守，反之亦然。这比固定策略的对手训练效率高得多，也是 AlphaGo/AlphaZero 系列的核心训练范式。

## 三、Q-Learning 核心公式

### 1. Q 值更新公式

$$Q(s, a) \leftarrow Q(s, a) + \alpha \left[ r + \gamma \max_{a'} Q(s', a') - Q(s, a) \right]$$

| 符号 | 含义 |
|------|------|
| $Q(s, a)$ | 状态 $s$ 下执行动作 $a$ 的 Q 值 |
| $\alpha$ | 学习率（Learning Rate），控制新经验覆盖旧记忆的速度 |
| $r$ | 执行动作后获得的即时奖励 |
| $\gamma$ | 折扣因子（Discount Factor），衡量未来奖励的当前价值 |
| $s'$ | 执行动作后到达的下一个状态 |
| $\max_{a'} Q(s', a')$ | 下一状态中最大的 Q 值（即"最优后续动作"的估值） |

### 2. TD 误差（Temporal Difference Error）

$$\delta = r + \gamma \max_{a'} Q(s', a') - Q(s, a)$$

> TD 误差是强化学习的"心跳信号"——它衡量的是**现实（r + 下一步最优估值）与预期（当前 Q 值）之间的差距**。差距越大，说明当前估计越不准，需要更多修正。Q-Learning 的本质就是用这个误差来逐步校准整张 Q 表。

### 3. ε-贪婪策略

$$a = \begin{cases} \text{random}(A) & \text{概率 } \varepsilon \\ \arg\max_a Q(s, a) & \text{概率 } 1 - \varepsilon \end{cases}$$

### 4. ε 衰减策略

$$\varepsilon \leftarrow \varepsilon \times \text{decay\_rate}$$

## 四、调参比对与分析

在开发过程中，主要调整了三个超参数：**学习率 α**、**折扣因子 γ** 和 **探索率 ε**。

### 1. 学习率 α

| 设置 | 表现 | 分析 |
|------|------|------|
| 过大（如 0.9） | Q 值震荡剧烈，难以收敛，容易遗忘之前学到的正确走法 | 每次更新步幅太大，像"金鱼记忆"——刚学到的重要经验被下一局的新经验直接覆盖 |
| 过小（如 0.001） | 收敛速度极慢，训练 2 万局后仍表现不佳 | 学习像"蜗牛爬坡"，每一步只吸收 0.1% 的新信息，样本利用率太低 |
| **最佳（0.1）** | 在保证收敛稳定性的前提下，拥有较快的学习速度 | 经验与记忆之间取得了良好平衡 |

### 2. 折扣因子 γ

- **设置（0.9）**：由于井字棋步数较少（最多 9 步），未来的奖励依然很重要。
- **含义**：意味着智能体会为了**两步之后的胜利**而努力布局，而不是只顾眼前一步的得失。

> γ = 0.9 在井字棋中是一个偏"远视"的设置。如果设得太低（如 0.1），智能体可能变得短视——只关注下一步能不能赢，而忽略了对面的杀招正在逼近。

### 3. 探索率 ε 与衰减策略

| 策略 | 表现 | 分析 |
|------|------|------|
| 固定 ε = 0.1 | 前期探索不足，训练初期容易陷入局部最优（例如只喜欢下角落，不懂防守） | 探索预算太少，智能体没机会"试错"出更好的走法 |
| **ε-decay（ε ×= 0.9999）** | 初期高 ε 保证充分探索，后期低 ε 保证利用已学知识、稳定胜率 | 从"广撒网"逐步过渡到"精准打击" |

**调参结论**：使用 **ε-decay** 策略的训练曲线比固定 ε 更加平滑，最终的胜率也更高。

> ε-decay 的直觉就像人类学习下棋：初学时要大胆尝试各种走法（哪怕很蠢），等积累足够经验后，就越来越少"乱下"，越来越多"有把握的下法"。衰减率 0.9999 意味着每局结束后 ε 只缩小万分之一，保证前期有充足的探索空间。

## 五、Debug 过程记录

在复现过程中，遇到了几个典型 Bug，记录如下：

### Bug 1：ValueError —— 非法落子

| 项目 | 内容 |
|------|------|
| **现象** | 程序运行时随机报错 |
| **原因** | 最初在更新 Q 值时，传入的 `next_state` 对应的棋盘已经满了，但智能体仍试图从中选点 |
| **解决** | 确保在 `env.step()` 之后检查 `env.done`，若结束则不再执行后续逻辑；在更新 Q 值时，如果 `done` 为 `True`，则将 `next_max_q` 设为 0 |

> 这是一个经典的"越界更新"问题：游戏已经结束了，但代码还在试图从终局状态继续选动作。本质上是因为 Q-Learning 的更新公式需要 `s'`（下一状态），而终局没有"下一状态"。修正方法就是加一个 `if done: break` 的保护逻辑。

### Bug 2：智能体从不 Block（不会防守）

| 项目 | 内容 |
|------|------|
| **现象** | 对手差一步就赢了，智能体却去下别的地方 |
| **原因** | 奖励函数中缺少对"失败"的惩罚，或者奖励权重不合理 |
| **解决** | 将失败奖励明确设为 -1，并确保 Q 更新公式中 `next_max_q` 计算正确，让智能体意识到某些走法会导致后续被击败 |

> 这个 Bug 暴露了一个关键认知：**强化学习只会优化你给它的信号**。如果失败没有代价，智能体就会"自私地"只顾进攻，因为它从未被告知"被对手连成一线"是一件坏事。Reward Design 是整个项目的灵魂。

### Bug 3：训练曲线剧烈震荡

| 项目 | 内容 |
|------|------|
| **现象** | 胜率在 0.4 到 0.8 之间来回跳动，无法收敛 |
| **原因** | 学习率 α 设置过高（0.5），导致新经验瞬间覆盖了旧记忆 |
| **解决** | 降低 α 至 0.1，并引入 ε 衰减机制，使训练后期趋于稳定 |

> 震荡的本质是**学习率与探索率双重过高**：一方面 α 太大让每次更新都"翻天覆地"，另一方面高 ε 不断引入随机动作产生噪声样本。两者叠加，Q 表就像一锅始终烧不开的水——温度（胜率）上去了又被搅乱。

## 六、总结

| 模块 | 核心收获 |
|------|---------|
| 环境设计 | 状态表示、合法动作过滤、胜负判定是任何 RL 环境的三要素 |
| Q-Learning | Q 表 + ε-贪婪 + TD 更新，构成了最经典的"试错学习"闭环 |
| Reward Design | 奖励函数是智能体的"价值观"，垃圾进垃圾出（GIGO） |
| Self-Play | 左右互搏让对手水平同步提升，数据效率远高于固定策略 |
| 调参经验 | α 控制学习速度，γ 控制远视程度，ε-decay 控制探索节奏——三者缺一不可 |
| Debug 思维 | RL 的 Bug 往往不在代码语法，而在"信号链路"：奖励对不对？状态传没传？done 检查了没？ |

> 井字棋是 RL 的"Hello World"，但它浓缩了强化学习的完整闭环：**环境 → 动作 → 奖励 → 更新 → 再决策**。把这套流程吃透，后续迁移到更复杂的项目（如 CartPole、Atari、甚至机器人控制）时，核心思路是一脉相承的——只是状态空间和神经网络替代了 Q 表而已。
